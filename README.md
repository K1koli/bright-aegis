# BRIGHT harness self-evolution — experiment code

Code for running AEGIS harness self-evolution on the BRIGHT retrieval benchmark, plus
the cross-domain and cross-benchmark evaluations used to test whether what it evolves
generalises.

The task agent is a frozen **Qwen3.5-9B** served by vLLM. The proposer (Digester /
Planner / Evolver / Critic) is **DeepSeek-V4-Flash**. Fitness is deterministic
**nDCG@10**, so nothing about the score depends on a judge model.

## First-time setup on a new machine

Requires **Python 3.12** and **git**.

```bash
git clone <this-repo> bright-aegis
cd bright-aegis

# 1. dependencies
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. HarnessX (the AEGIS engine) at the exact state these runs used
git clone https://github.com/Darwin-Agent/HarnessX.git third_party/HarnessX
git -C third_party/HarnessX checkout 90f5d2d
git -C third_party/HarnessX apply ../../patches/harnessx-90f5d2d-to-worktree.patch
pip install -e third_party/HarnessX

# 3. credentials
cp .env.example .env.local         # then edit it
```

### Why a patch instead of a vendored copy or a submodule

The branch these experiments ran on (`bright-graded-fitness`) is **local only** — its
six commits were never pushed to `Darwin-Agent/HarnessX`. `90f5d2d` is the last commit
that *is* public, so `patches/harnessx-90f5d2d-to-worktree.patch` captures the complete
delta from that public commit (11 files, including the new `gates/fitness.py`,
`budget.py`, the structure-gate scratch-file exemption, the Windows `Bash` fix, the
empty-assistant-turn fix and the cache-token accounting).

Verify the patch before trusting it:

```bash
git -C third_party/HarnessX apply --check --reverse ../../patches/harnessx-90f5d2d-to-worktree.patch
echo $?    # 0 = the patch's result matches a working tree exactly
```

### Point it at your vLLM endpoint

`.env.local` has two roles — the frozen task agent and the proposer. See
`.env.example` for the full list. The task agent is the only thing that needs a GPU.

## Running things

Every entry point takes `--help`. All of them read `.env.local`.

### 1. Evolve a harness on one BRIGHT domain

```bash
python src/bright_harness/evolve.py \
  --domain biology --all-queries \
  --rounds 15 --patience 3 --digester-concurrency 8 \
  --run-root runs/bio-full-T15
```

`--all-queries` evaluates the whole domain task set each round; leaving it out samples
`--n-dev` queries. A per-round `parse_rate` guard aborts the run if the task agent stops
answering (that failure mode silently produced all-zero scores once).

### 2. Evaluate one config on one domain

```bash
python src/bright_harness/eval_config.py \
  --config runs/bio-full-T15/R9/applied/merged.yaml \
  --domain biology --all-queries --split all
```

### 3. Cross-domain matrix (N arms × M cells)

```bash
python src/bright_harness/cross_eval.py \
  --arm bioR9=runs/bio-full-T15/R9/applied/merged.yaml \
  --arm robR7=runs/rob-3to1/R7/config.yaml \
  --cell biology:all --cell economics:all --cell robotics:all \
  --out runs/cross-eval/all-arms \
  --reuse-baseline
```

Caches each cell's `H_0` under `<cell>/_H0/` so repeated arms share one baseline.

### 4. Cross-benchmark OOD

```bash
# BEIR — real retrieval, no chunking (SciFact: 300 queries, 5,183 abstracts)
python src/beir/eval_beir.py --dataset scifact \
  --arm bm25=bm25 --arm h0=builtin \
  --arm bio=runs/bio-full-T15/R9/applied/merged.yaml \
  --arm rob=runs/rob-3to1/R7/config.yaml

# BIRCO — candidate pool given, so NO retrieval and NO chunking
python src/birco/eval_birco.py --task arguana \
  --arm echo=echo --arm h0=builtin \
  --arm bio=runs/bio-full-T15/R9/applied/merged.yaml \
  --arm rob=runs/rob-3to1/R7/config.yaml \
  --force-k 10
```

`--force-k` caps `RetrievalPolicyProcessor.retrieve_k`, so every arm sees the same
number of passages. `want = min(k_requested, retrieve_k)`, so capping at 10 makes arms
that request 30 or 50 see 10 too — needed on BIRCO, where the pool is fixed and only
ordering can differ. **Do not** pass it on BEIR, where a deeper pool genuinely retrieves
different documents and is part of what was evolved.

### 5. Inspect why an arm won or lost a single query

```bash
python src/birco/probe_birco.py --task arguana --auto 2
```

Prints the model's raw output and the full per-step journal for the queries where the
baseline beat the evolved harnesses by the most.

### 6. Plots and cost

```bash
python src/bright_harness/plot_curve.py --help
python src/bright_harness/cost_report.py --help
```

## Notes for whoever picks this up

- **`temperature=0` is not bit-reproducible here.** The same config measured twice
  differs by ~0.004–0.013 nDCG@10, and a repeat-measurement of `H_0` moved by 0.010.
  Only deltas measured **within one session** are trustworthy; compare against a
  freshly measured `H_0` on the same cell, never against a number from another run.
- **The gate set does not check for score improvement.** `structure`, `novelty`,
  `canonicalize`, `counterfactual`, `replay` are integrity gates; the graded `fitness`
  gate that would require a mean improvement exists in the patch but is **off unless
  `--fitness-gate` is passed**, and self-skips without a wired context. A shipped
  candidate is measured only in the following round, and there is no rollback.
- **`tracer.base_dir`** in a candidate config is overwritten per round by
  `round_driver._force_tracer_dir`; a config that pins it does not redirect the journal.
- **Rendered `trajectories/*.md` do not carry per-step counts** (`steps: 0`,
  `tools_used: []`), even though `raw/*.jsonl` has the full journal. Read `raw/` when
  you need to know what the model actually did.
- **`max_tokens=2048` truncates** 2–10% of answers, which parse as empty and score 0.
  Reported scores are therefore lower bounds.
